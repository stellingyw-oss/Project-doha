### D. PR #2 리뷰 보완 3건 (2026-11-25 추가 커밋)

ChatGPT 검토(`downloads/chatgpt_doha_pr2_review_20261125.md`)가 PR #2를 병합 후보로 채택하면서,
공개 배포 전에 요구한 3건입니다. 영우님 승인 아래 **이 브랜치에만** 반영했습니다.

**D-1. 음성 자막(STT) 인식 비활성 — 공개 v0.1.4 안전**
- 문제: 녹음 동의 문구는 "이 브라우저에만 저장"인데, 캔버스의 `음성 자막 변환` 토글은
  `SpeechRecognition`을 시작해 **오디오를 브라우저 제조사 서버로 보낼 수 있었습니다.**
- 조치: `src/index.src.html`에 `var STT_ENABLED=false;`를 두고 **인식기가 생길 수 있는 경로를 모두 닫았습니다.**
  - `startStt()` 첫 줄에서 `if(!STT_ENABLED) return;` — 인식기 생성(`new C()`)·시작(`r.start()`) 이전에 끊습니다.
  - `setStt(true)`(스크립트 경로 포함) → 준비 중 안내만 하고 `false`를 반환.
  - `sttCommit()`도 스위치가 꺼져 있으면 즉시 반환(방어).
  - 마이크 시작 경로의 `if(STT_ENABLED && stt.on) startStt();` — 조건을 명시.
- UI: 토글 라벨 `음성 자막 변환 (v0.2 준비 중)`, `aria-disabled="true"`, 점선 테두리와 흐린 글자로
  **"누를 수 있는 기능"으로 보이지 않게** 했습니다. 누르면 "음성 자막은 v0.2에서 준비 중이에요 —
  지금은 원본 녹음·바로 듣기·직접 입력으로 놀 수 있어요" 토스트가 뜨고, 안내줄은
  "지금은 녹음·바로 듣기·직접 입력으로 놀아요 · 원본 녹음은 이 브라우저에만 저장"입니다.
- 그대로 유지: **원본 녹음·저장·바로 듣기·직접 입력**은 전부 정상. 인식 코드는 v0.2에서 다시 켤 수 있게
  남겨 두었지만, `STT_ENABLED=false`인 동안에는 실행되지 않습니다.
- `__DOHA.stt()`가 `enabled`를 함께 돌려주어 테스트가 스위치 상태를 직접 확인합니다.

**D-2. 문구 3곳 정정 — 예시와 자기 기록을 구별**
| 위치 | 이전 | 이후 |
|---|---|---|
| 공룡 예시 그림 | 배지 `예시 장면` + 설명 `어제 [[NAME]]의 상상 · “공룡이…”` | 배지 **`이렇게 놀 수 있어요`** + 설명 **`예시 장면`** · “공룡이 우리 집 거실에 나타났어!” |
| 홈 안내 | `말하는 순간, [[NAME]]만의 세상이 화면에 펼쳐져요. 끝나면 목소리와 장면이 담긴 상상 영화로 남아요.` | **`함께 지어낸 이야기와 오늘의 목소리를 간직해요.`** `오늘 만든 장면은 상상 영화로 남아요.` |
| 타임캡슐 | `정해진 날이 되면 [[NAME]]에게 알림이 가고, 그날의 상상 영화가 그대로 재생됩니다.` | **`타임캡슐은 가족만 열 수 있어요. 미리보기 · 날짜 알림은 준비 중이에요.`** |

`예시 장면`은 설명 앞머리에 `<b>`로 남겨, 홈의 예시 그림이 **샘플**임을 계속 알 수 있게 했습니다.

**D-3. 전체 내보내기 음성 누락 검증 추가**
- 기존에는 개별 내보내기(`기록 + 음성 JSON`)만 실제로 눌렀습니다. 부모가 기기를 바꾸기 전 믿고 누르는
  버튼은 **전체 기록 내보내기**라서, 같은 누락 조건에서 그 버튼을 실제로 누르는 검사를 추가했습니다.
- `src/verify_v014.py: check_missing_audio_export_all()` — 작품 2편(각 원본 음성 1구간)을 만든 뒤
  **한 편의 음성 1구간만** IndexedDB에서 지우고 새로고침해 메모리 Blob 회수 경로까지 끊습니다.
  그 다음 앨범 상단의 `전체 기록 내보내기 (JSON)`을 실제 클릭해 다음을 확인합니다.
  - JSON `works` 2편 · `manifest.workCount=2` · `manifest.missingAudioClipCount=1`
  - `manifest.missingAudioNote`("… 찾지 못해 …") · 파일 `note`("… 1구간이 빠져 있습니다")
  - 화면 토스트: `내 기록 2편을 한 파일로 내보냈지만 원본 음성 1구간이 빠졌어요`
- 같은 누락 작품에서 **`기록 정보 JSON`(metadataOnly)** 도 눌러, `missingAudioClipCount`가 없고
  누락 경고 토스트가 뜨지 않는지 확인했습니다.

## 4. 아직 검증하지 않은 것 (미검증으로 표기)

- **실기기 Safari / 아이패드 터치 실측**: 위 수치는 전부 로컬 headless Chromium(가짜 마이크) 결과입니다.
  iOS Safari의 `pointer-events`, 오디오 자동재생 정책, safe-area, 상태바 색은 실기기에서 눈으로 봐야 합니다.
- **실제 마이크·권한 다이얼로그**: 가짜 장치로만 확인. 실제 iOS 권한 거부/허용 UI는 미확인.
- **음성 자막 변환(STT)**: 공개 v0.1.4에서는 **인식기를 아예 시작하지 않으므로** 실서버 인식 품질은
  이 버전의 검증 대상이 아닙니다(오디오가 외부로 나가지 않음). v0.2에서 외부 처리 고지를 갖추고 켤 때 다시 측정합니다.
- **영상·목소리 합성, 부모 리포트**: 원래 v0.4 / v0.6 로드맵, 이번에도 미구현.
