## 1. v0.1.2 변경 내역 (저장 안전성 P0 6건 + 기록 내보내기·삭제)

| # | 문제 | v0.1.2에서 어떻게 고쳤나 |
|---|---|---|
| P0-1 | IndexedDB가 안 열리면 **음성이 빠진 채로 저장 성공(`true`)** 을 돌려주고, localStorage 저장마저 실패해도 성공으로 처리됐다 | `putWork()`가 `true/false` 대신 **저장 상태**를 돌려준다 — `SAVED_COMPLETE`(작품+원본 음성 모두 커밋·재조회 확인) / `SAVED_TEXT_ONLY`(기록만 저장, 음성 없음) / `SAVE_FAILED`(아무것도 확인되지 않음). localStorage 폴백도 **다시 읽어 존재를 확인**했을 때만 성공으로 본다 |
| P0-2 | **영구 저장이 끝나기 전에** 메모리 앨범 목록과 `state.savedEntry`를 먼저 바꿔, 새로고침하면 사라지는 기록이 앨범에 보였다 | IndexedDB 트랜잭션 **커밋 → 다시 읽어 확인**까지 끝난 뒤에만 `albumCache`에 반영한다. 실패하면 앨범(내 기록)에 넣지 않는다 |
| P0-3 | 저장 결과를 기다리지 않고 화면을 넘겼다 (`saveEntry(); go("movie")`) | `endStory()`가 **마이크 종료 → 원본 수집 → 영화 생성 → 저장 완료** 순서를 `await`로 지킨 뒤에만 화면을 넘긴다. 저장 중에는 **"저장하는 중" 오버레이**가 뜨고 저장 버튼이 잠기며, `go()`가 다른 화면 전환을 막는다. MY UNIVERSE 저장 버튼도 저장이 확인된 뒤에만 앨범으로 이동한다 |
| P0-4 | 녹음이 **직전 장면 하나를 덮어썼고**, `audioDur`를 **40초로 강제 절단**했다 | 장면마다 `takes[]`(테이크 배열)를 두어 **같은 장면에서 여러 번 녹음해도 모든 구간을 보존**한다. 길이는 실제 오디오 길이(측정 불가 시 녹음한 시간)를 그대로 쓰고 **상한을 없앴다**. 영화는 테이크를 순서대로 이어 재생한다 |
| P0-5 | 전역 `recChunks`·`recMime`와 700ms 대기 때문에 **늦은 종료 이벤트·빠른 재시작·새 작품 시작**이 겹치면 녹음이 유실되거나 다른 작품에 붙었다 | 녹음 **세션마다 자기 버퍼·자기 종료 약속**을 가진다. `stopMic()`은 `onstop` → Blob 수집 → 장면 부착(길이 측정)까지 기다린 뒤 끝나고, 그 전에는 새 녹음·새 작품·저장을 시작하지 않는다. 녹음 시작 시점의 장면·작품 id를 기억해 **다른 작품으로 넘어간 뒤 늦게 온 녹음은 버린다**(잘못 붙이지 않음). 테이크가 비면 유실을 사용자에게 알린다 |
| P0-6 | v0.1 `localStorage` 기록을 IndexedDB로 옮길 때 **저장 결과를 확인하지 않고 원본을 삭제**했다 | 이관한 **모든 기록이 실제로 다시 읽혀 확인된 뒤에만** `doha.v01.album` 원본을 지운다. 하나라도 실패하면 원본을 그대로 두고 다음 실행에서 다시 시도한다 |
| 신규 | 배포 주소가 바뀌면 기존 IndexedDB 기록에 접근할 수 없었다 | MY UNIVERSE 카드마다 **`내보내기` · `삭제`** 버튼, 상단에 **`전체 기록 내보내기 (JSON)`**. 내보내기 파일에는 작품 메타·장면·자막·관찰 노트·질문·아빠의 기록 + **원본 음성(base64)** + manifest(편수·장면 수·음성 개수·용량)가 들어간다. 저장이 `SAVED_TEXT_ONLY`/`SAVE_FAILED`여도 그 화면에서 **`파일로 내려받기`** 로 메모리의 목소리까지 꺼낼 수 있다. 삭제는 확인창을 거쳐 작품 기록과 그 원본 음성(clips)을 함께 지운다 |

### 저장 상태 4단계

| 상태 | 뜻 | 화면 |
|---|---|---|
| `SAVING` | 원본 음성 수집·IndexedDB 쓰기 진행 중 | "저장하는 중" 오버레이, 저장 버튼 잠금, 화면 전환 차단 |
| `SAVED_COMPLETE` | 작품 + 원본 음성 모두 저장·확인됨 | 안내 배너 없음, 앨범 반영 |
| `SAVED_TEXT_ONLY` | 장면·자막·메모는 저장, **원본 음성은 저장 안 됨**(IndexedDB 불가·용량 초과 등) | 노란 배너 + `다시 저장` · `파일로 내려받기` |
| `SAVE_FAILED` | 아무것도 확인되지 않음 | 빨간 배너 + `다시 저장` · `파일로 내려받기`, 앨범에 넣지 않음 |

### 검증 (자동)

`src/verify_v012.py` — 헤드리스 Chromium + 가짜 마이크로 아래 **59개 항목**을 확인합니다(전부 통과).

- 종료 클릭 직후 `SAVING`·오버레이·앨범 미반영·저장 버튼 잠금, 저장 확인 뒤 `SAVED_COMPLETE`·영화 화면 전환
- 한 장면 2회 녹음 → 테이크 2개 보존, 빠른 재시작 3회에도 테이크가 섞이지 않음, **42초 녹음이 40초로 잘리지 않음**
- 녹음 중 종료 → 마지막 테이크까지 저장, 마이크 정지·유실 0
- 새로고침 뒤 테이크 전부 복원, 개별/전체 내보내기 파일의 장면·자막·음성·manifest 검증
- 삭제 취소 시 유지 / 삭제 확인 시 works·clips 함께 삭제 / 지운 작품을 다시 저장하면 지운 id가 아니라 새 기록
- IndexedDB 불가 → `SAVED_TEXT_ONLY` + 배너 + 파일 내려받기(음성 포함), 새로고침 뒤에도 기록 유지
- 저장 완전 실패 → `SAVE_FAILED` + 앨범 미반영 + 파일 내려받기(메모리 음성 포함)

## 5. 파일 구조

```
project-doha/
  index.html                 ← 최종 산출물 (이미지 내장, 단일 파일)
  assets/
    scene1_livingroom.png    ← 생성 원본 4장 (1672×941)
    scene2_space.png
    scene3_giant.png
    scene4_spaceship.png
    web/                     ← 내장용으로 줄인 JPEG + 그림체 미리보기 8장
  src/
    index.src.html           ← 원본 소스 ({{IMG_*}}, {{T_*}} 자리표시자, [[NAME]] 이름 토큰)
    prepare_assets.py        ← 원본 PNG → 웹용 JPEG + 그림체 썸네일 생성
    build.py                 ← 소스를 base64 내장 단일 index.html로 빌드
    check.py                 ← 3개 화면 크기에서 전체 흐름 자동 점검 + 스크린샷
    verify_v011.py           ← v0.1.1 P0 검증(저장·복원·마이크·권한 거부)
    verify_v012.py           ← v0.1.2 P0 6건·내보내기·삭제·이관 안전성 검증
    test2.py                 ← 그림체 시트·마이크·영화 종료·앨범 저장 점검
    shots.py                 ← 검토용 스크린샷 촬영
```

### 수정하는 방법

1. `src/index.src.html` 수정 → `python3 project-doha/src/build.py`
2. 그림체 썸네일·이미지를 바꾸려면 `python3 project-doha/src/prepare_assets.py` 먼저 실행 후 빌드
3. 문구·색·장면을 바꾸는 곳은 `index.src.html`의 `STYLES` / `CHIPS` / `SCENE_INFO` / CSS 변수(`:root`)

### 저장 구조 (IndexedDB `doha-universe`)

| 스토어 | 키 | 내용 |
|---|---|---|
| `works` | `id` | 작품 메타(번호·날짜·제목·그림체·태그·관찰 노트·질문·메모) + 장면 배열(장면 키·자막·틴트·그림체·음성 길이 `audioDur`·`clipIds`·`takeCount`) |
| `clips` | `id` | `workId`·`sceneIndex`·`takeIndex`별 녹음 원본 `Blob` + 길이 |

  "works": [{
    "record": {"id": "...", "no": 3, "date": "2026-11-25", "title": "...", "scenes": [ ... ]},

## 6. 함께 써볼 때 체크할 것

1. 시키지 않아도 다음 장면을 말하는가
2. 자기 상상이 화면이 되는 걸 재미있어 하는가 (어떤 그림체에서 오래 머무는가)
3. 대화가 더 풍성해지는가 (어른이 끼어들 여지가 있는가)
4. 끝난 기록을 다시 보고 싶어 하는가
5. 다른 보호자가 돈을 낼 것 같은가

## 8. 안전·개인정보 원칙

- 광고·외부 링크·보상 시스템 없음
- 심리 진단·점수·평가 문구 없음 — 관찰 노트는 사실 기록만, "심리 상태를 단정하지 않습니다" 상시 표시
- 아이의 상상을 검열하지 않음 — 엉뚱한 말도 그대로 장면이 됨
- 모든 데이터는 기기 안에만 저장(IndexedDB/localStorage), 서버 전송 없음
- 이미지·목소리는 **사용자가 직접 내보내기를 누를 때만** 파일로 나감 — 그 파일에는 목소리가 들어 있으니 안전한 곳에 보관
- 이 저장소와 앱 기본값에는 아이의 실명·나이·학년이 들어가지 않음 (이름은 사용자가 입력한 경우에만 그 브라우저에 저장)
